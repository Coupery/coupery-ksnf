# Ed25519 profile

This document fixes the byte and hash profile for
`coupery-ksnf/ed25519/v1`. “Must” and “must not” are conformance requirements.

The profile emits ordinary Ed25519 public keys and signatures. Its internal
messages are KSNF messages, not RFC 9591 FROST messages.

## Identifiers

| Field | Value |
|---|---|
| Profile ID | `coupery-ksnf/ed25519/v1` |
| Structured-message byte | `0x02` |
| Material header | `KSNFE1M1` |
| Journal header | `KSNFE1J1` |
| Vector directory | `test-vectors/v1-ed25519` |

Every structured protocol object starts with `0x02`. Root packages also bind
the full profile ID. Persistent records use the profile-specific headers.
Public keys and final signatures are the only untagged objects.

## Group and encodings

The group is the prime-order subgroup of Edwards25519, with order

```text
ℓ = 2^252 + 27742317777372353535851937790883648493
```

and the RFC 8032 base point.

- Scalars are canonical 32-byte little-endian integers below `ℓ`.
- Nonidentity points are canonical 32-byte compressed Edwards-Y encodings.
- Internal point decoders reject the identity, malformed and noncanonical
  encodings, torsion points, and points with a nonzero torsion component.
- An internal slot that can hold the identity uses 33 bytes. `00` followed by
  32 zero bytes means identity. `01` followed by a valid nonidentity point
  means that point. No other form is valid.

A vault key is the 32-byte encoding of `Q`. A final signature is `R || z`,
where both fields are 32 bytes and `z < ℓ`. Honest `R` values lie in the
prime-order subgroup.

The crate's decoder is strict. Signatures produced by the crate also verify
with ordinary RFC 8032 cofactored or cofactorless verification because honest
`Q` and `R` are prime-order points.

## Hashes

All protocol scalar hashes use SHA-512 and reduce its 64-byte little-endian
output modulo `ℓ`.
Let `Ω` be the 32-byte little-endian encoding of `2^255 - 19`, with its sign bit
clear:

```text
edffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff7f
```

`Ω` is not a canonical Edwards25519 point encoding. KSNF's internal scalar
hashes are

```text
SHA512(Ω || tag || u64be(len(x)) || x) mod ℓ
```

with these one-byte tags:

| Tag | Use |
|---|---|
| `0x01` | Redistribution commitments |
| `0x02` | Private member commitments |
| `0x03` | Nonce-share commitments |
| `0x04` | FROST binding factors |

The final challenge is deliberately unprefixed:

```text
c = SHA512(R || Q || message) mod ℓ
```

This is the RFC 8032 challenge used by FROST(Ed25519, SHA-512). The invalid
point prefix `Ω` makes every internal hash input disjoint from every final
challenge input.

## Nonces

Each leaf samples two fresh nonzero scalars from a cryptographic random number
generator. Nonces are secret, ceremony-bound, volatile, and used once.
Deterministic Ed25519 seed-based nonce generation is not part of this profile.

The same vault key must not also be used by ordinary single-signer Ed25519 or
another protocol. Such reuse is outside the proof and can invalidate its nonce
assumptions.

## Verification and proof boundary

The Ed25519 profile lift preserves the KSNF theorem under OMDL in the
prime-order Edwards25519 subgroup and SHA-512 modeled as a random oracle. Its
only added term is the statistical distance from reducing 512-bit strings:

```text
δ_profile = Q_red · r(ℓ - r) / (ℓ · 2^512) < Q_red · 2^-261
r = 2^512 mod ℓ
```

`Q_red` counts distinct scalar-valued SHA-512 derivations made by the
adversary, honest parties, and final verification.

The full cofactored-verifier lift depends on Property P: the base proof must
index, program, and fork final-challenge queries by their exact labels, never
by commitment points alone. The strict-verifier lift and honest RFC
interoperability do not depend on that property.

### Property P audit

The current base proof satisfies Property P.

1. The single-entry fork identifies the exact `(R, Q, message)` oracle input
   and changes only that entry.
2. Confinement compares full challenge inputs. It never groups queries by
   their commitment point or maps a point back to an input label.
3. Extraction subtracts two equations carrying the same label. It cancels the
   associated point without decomposing or re-encoding it.

An exhaustive `H_sig` occurrence check finds no other programming, lookup, or
collision event. Torsion-shifted encodings therefore remain distinct oracle
labels and cost ordinary query count, not a factor of eight. This audit is the
only premise added by the full cofactored-verifier lift.

The theorem covers post-setup signing and redistribution with valid initial
shares. It does not prove a malicious DKG, storage correctness, side-channel
resistance, Ed25519ctx, Ed25519ph, batch verification, noncanonical verifier
behavior, adversarially chosen public keys, or key use outside Ed-KSNF.

## WebAuthn boundary

For a WebAuthn EdDSA credential, the application publishes the vault key as an
Ed25519 COSE key with `alg = -8` and `crv = 6`, then asks KSNF to sign exactly

```text
authenticatorData || SHA256(clientDataJSON)
```

The application still owns CBOR, credential IDs, relying-party metadata, user
handles, counters, presence and authorization policy, transport, and initial
provisioning.
